## 3. 광학 아키텍처 1차 선별

README 단계 C의 최종 결정은 문헌 게이트를 통과한 뒤 `research/04-architecture.md`에 기록한다. 여기서는 예산과 안전 제약만으로 걸러낸 **선별 결과**를 둔다.

| 후보 | 개요 | 1차 판정 | 이유 |
|---|---|---|---|
| **A1. 페퍼스 고스트** | 위를 향한 패널 + 45° 하프미러. 상은 유리 **뒤쪽**에 맺힌다 | 후보 | 가장 싸고 단순하다. 다만 손이 유리에 막혀 상을 "직접" 만질 수 없다. 터치 영역을 유리 앞에 따로 두는 **간접 터치**가 된다 |
| **A2. 공중 실상 (재귀반사형 AIRR 또는 이면 코너 반사 플레이트)** | 상이 플레이트 **앞쪽** 공중에 실상으로 맺힌다 | **우선 후보** | 손가락과 상이 같은 위치에 있어 직접 터치가 된다. 초음파 초점을 상 위치에 맞출 수 있다. 다만 광 효율이 낮아 고휘도 패널이 필요하다 (가설) |
| B. 무안경 라이트필드 | 상용 라이트필드 디스플레이 | 보류 | 가격 미확인. 상이 블록 안에 있어 A1처럼 간접 터치가 된다 |
| C. 레이저 계산 홀로그램 | SLM + 레이저 | **제외** | 레이저 무사용 원칙과 예산 모두에 어긋난다 |

- **이 스펙의 기준은 A2**로 하고, A1을 대체안으로 둔다.
- 결정 지점은 **2주 차 광학 벤치 시험**이다 (8장 게이트 G1).
  - 실측할 항목: A2 상의 휘도·대비가 500 lux에서 OPT-02를 만족하는지 (절차: `research/07-test-plan.md` 4장 B-01)
  - 만족하지 못하면 A1(간접 터치)로 전환한다

> 문헌 확인 필요 (`research/01-search-log.csv`에 등록할 것):
> - 공중 실상과 초음파 햅틱의 결합 사례: HaptoMime, Monnai 외, UIST 2014

## 4. 시스템 구성

```text
                ┌───────────────────────── 외함 (차광 후드) ─────────────────────────┐
  사용자 손 ──▶ │  [손 추적 센서] ──USB──▶ ┌──────────────┐ ──HDMI──▶ [고휘도 패널]    │
                │                           │  호스트       │                 │           │
                │  [조도 센서] ─I²C─┐       │  (앱·로그)    │          [결상 광학 A2/A1] │
                │                   ▼       └──────┬───────┘                 │           │
                │  [안전 인터록]─▶ [MCU] ◀──USB 직렬──┘                       ▼           │
                │     E-stop·온도    │                                    공중 상 ◀──┐  │
                │                    ▼                                               │  │
                │            [초음파 위상배열] ──── 초점 ───────────────────────────┘  │
                └────────────────────────────────────────────────────────────────────┘
```

### 좌표계
- 원점: 결상 플레이트 중심 (A1이면 하프미러 중심)
- 축 방향: +X 사용자 기준 오른쪽, +Y 위, +Z 사용자 쪽, 단위 mm
- 정렬: 센서 좌표 → 시스템 좌표 변환은 시작 시 4점 정렬로 구한다 (FR-09)

### 상호작용 공간
- 공중 상 중심 기준 가로 150 × 세로 100 × 깊이 100 mm (초기값)
- 버튼 5개를 이 안에 배치한다

### 5.4 가상 버튼 상태기계 (프롬프트 E2)

#### 입력
매 추적 프레임마다 다음을 받는다.
- 검지 끝 위치 p, 속도 v
- 추적 신뢰도 c
- 버튼 평면까지의 침투 깊이 d (버튼 앞면 기준, 누르는 방향이 +)

#### 파라미터 (모두 초기값)

| 이름 | 값 | 의미 |
|---|---|---|
| R_hover | 25 mm | 버튼 중심에서 hover로 인정하는 반경 |
| D_arm | 0 mm | 이 깊이를 넘으면 arm |
| D_act_in / D_act_out | 10 mm / 5 mm | activate 진입·해제 깊이. 둘의 차이가 히스테리시스 |
| T_dwell | 80 ms | arm 상태에서 D_act_in 이상을 유지해야 하는 시간 (debounce) |
| V_max | 1.0 m/s | 이보다 빠른 통과는 activate로 보지 않는다 (스쳐 지나감 방지) |
| C_min | 0.6 | 이 신뢰도 미만은 추적 상실 후보로 본다 |
| T_lost | 150 ms | 신뢰도 미달이 이만큼 이어지면 tracking-lost |
| T_refractory | 300 ms | activate 후 같은 버튼을 다시 activate할 수 없는 시간 |

#### 전이표

| 현재 | 조건 | 다음 | 출력 |
|---|---|---|---|
| idle | 버튼 중심과의 거리 < R_hover, c ≥ C_min | hover | 시각: 하이라이트 |
| hover | 거리 > R_hover + 5 mm | idle | 시각: 해제 |
| hover | d > D_arm | arm | 햅틱: 약한 펄스<br>로그 `arm` |
| arm | d ≥ D_act_in 상태가 T_dwell 동안 유지, \|v\| < V_max | activate | 시각: 클릭<br>햅틱: 클릭 패턴<br>로그 `activate` |
| arm | d < D_arm 또는 거리 > R_hover | cancel | 로그 `cancel` |
| activate | d < D_act_out | hover | refractory 타이머 시작 |
| cancel | 즉시 | hover 또는 idle | — |
| 어느 상태든 | c < C_min 상태가 T_lost 동안 지속 | tracking-lost | 햅틱 정지<br>시각: 추적 상실 표시<br>로그 |
| tracking-lost | c ≥ C_min 상태가 100 ms 지속 | idle | 로그 |
| 어느 상태든 | 안전 인터록 신호 또는 MCU 무응답 | safety-stop | 햅틱 전원 차단<br>로그 `error_code` |
| safety-stop | 원인 해소 + 운영자 수동 해제 | idle | 로그 |

#### 동시 처리 규칙
- 한 번에 activate할 수 있는 버튼은 1개다.
- 여러 버튼이 hover 조건을 만족하면 가장 가까운 버튼만 처리한다.

- **전제:** 선택한 손 추적 센서의 SDK를 Python에서 쓸 수 있어야 한다. 1주 차에 확인한다.
  - 쓸 수 없다면 P1로 전환한다.

### 6.1 모듈 간 메시지 (P3 기준 초안)

**브리지 → 렌더러 (WebSocket, JSON, 60 Hz 이상)**
```json
{"t": 1728712345.123, "type": "hand", "tip": [12.3, 40.1, 55.0], "vel": [0.0, -0.1, 0.0], "conf": 0.92}
{"t": 1728712345.130, "type": "lux", "value": 480}
```

**렌더러 → 브리지 (상태기계 이벤트)**
```json
{"t": 1728712345.140, "type": "button", "id": 2, "state": "activate"}
```

**브리지 → MCU (USB 직렬, 고정 길이 바이너리 프레임)**
```text
[0xA5][cmd][button_id][pattern_id][seq][crc8]
cmd: 0x01 = 출력, 0x02 = 정지, 0x10 = 하트비트
```

**MCU → 브리지**
- 응답 형식: `[0x5A][seq][status][temp_c×2][crc8]`
- status 비트 0: E-stop
- status 비트 1: 과열
- status 비트 2: 워치독 발동

> **상태기계를 어디서 돌릴지:** 이 초안은 렌더러에 두고, 브리지는 결과 이벤트만 받는다.
> 대안은 브리지(Python)에 두는 것이다. 그러면 단위시험과 로그가 쉬워진다.
> 이 결정은 1주 차 구현 계획(프롬프트 E1)에서 확정한다.
